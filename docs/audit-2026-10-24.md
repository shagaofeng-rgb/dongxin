# 网站与后台自检记录 — 2026-10-24

## 范围与方法

- 公开站点：从生产站点地图枚举页面，检查 HTTP 状态、标题、说明、主标题及站内链接；对首页、手机导航和后台手机端进行浏览器截图与交互检查。
- 后台：在已授权的管理会话中打开概览、访客与来源、访客记录、访问轨迹、询盘、WhatsApp 和内容清单；记录页面响应与数据状态。
- 数据：只读核查专用 Supabase 项目的事件、会话、询盘、国家字段以及安全/性能建议。检查应用中的追踪、表单及后台查询路径。

## 已确认的基线

- 原生产站点地图包含 84 个公开 URL；84 个页面均返回成功状态，79 个站内目标没有发现 404，每页有一个 H1 和 description，但全部缺少 canonical。
- 后台页面能读取真实数据；检查时概览近 7 天显示 20 次浏览、19 个匿名访客、0 条询盘和 0 次 WhatsApp 点击。这些数字是当时的实时快照，不是演示值。
- 数据库有真实事件与会话，国家字段来自 Vercel 边缘定位；大部分历史会话没有浏览器来源，因此不能把“直接访问”理解为已验证的营销渠道。
- 后台七个主要页面首次打开约 0.7–1.2 秒；产品清单首次可能先显示加载态，再出现真实目录数据。

## 已实施的修正

- 修复手机菜单背景透出，并在菜单打开时隐藏会遮挡内容的 WhatsApp 悬浮入口。
- 统一公开页 canonical；管理登录及后台设为 noindex；robots 不抓取 API 和身份验证路径。
- 页面切换或返回可见时补全页面浏览与离开事件，来源/国家按每次访问的首次浏览计数；优先识别 UTM 来源，避免按多次浏览重复计数。
- 后台增加国家/地区汇总和数据口径说明；数据库补齐会话及询盘关联索引，保持原有服务端权限规则。
- 对追踪与询盘接口增加大小、字段和来源校验；避免重复触发“开始填写”事件，并使网络失败显示正常错误状态。
- 清理上线页面中的预览/占位提示。没有批准的 3D、视频、下载文件时，提供真实的图片浏览、联系入口或清晰的无数据状态，不伪造资产。
- 产品菜单“按类型”入口改为实际过滤结果；隐私说明改为与当前表单/匿名统计实现一致的事实描述。

## 内容与数据边界

- 产品和文章后台清单读取当前网站目录源码，是只读内容清单；访客、来源、国家、询盘与 WhatsApp 数值读取数据库，不使用模拟数据。
- 国家为网络定位估计，来源受浏览器 referrer 策略、UTM 缺失及匿名访问限制。它们不能证明个人身份或实际所在地。
- 当前没有可发布的交互式 3D 文件或产品视频。若需上线这些内容，仍须提供经批准的原始媒体。网站表单保存到后台，不额外发送邮件通知。
- 没有进行真实客户询盘或 WhatsApp 对话的代发测试；只能验证入口、接口校验与已存在记录的读取。
- 管理员仍使用此前指定且曾在聊天中公开的密码；独立 Supabase 项目的泄漏密码保护目前未启用。这两项需要账号所有人后续自行处理。数据库安全检查中的四项“开启 RLS 但没有公开访问策略”属于服务端专用表的预期设置，未因此开放表权限。

## 上线复核

本地生产构建下，站点地图中的 81 个页面及 79 个站内链接目标全部通过 HTTP、description、canonical 和单一 H1 检查，没有发现 404。手机宽度下抽查了 16 类页面模板，均无横向溢出及加载失败的图片。390px 手机和 820px 平板的首页、导航抽屉、二级菜单、产品类型筛选及悬浮入口完成视觉与交互复核。平板宽度已切换到折叠导航；手机菜单展开后会隐藏悬浮入口，选择导航链接后会关闭菜单。

正式域名上线后再次扫描 81 个公开页面、79 个站内链接目标，HTTP、description、canonical 和单一 H1 均通过，无断链。生产站点的手机页面和后台手机导航已做浏览器复核。受保护的后台登录会话中，近 7 天概览显示 25 次页面浏览、18 名匿名访客、0 条询盘及 0 次 WhatsApp 点击；流量分析显示 21 次访问和美国、英国等国家/地区汇总。访客列表共 27 条记录，按每页 20 条分成两页，翻页时页面 URL 和汇总指标保持不变；访问详情可查看实际记录的会话事件。以上均为核查时刻的数据库快照，会随访问变化。

以上抽查不等于对每种浏览器、网络条件和真实客户表单行为的穷尽测试。没有真实客户询盘样本可验证从提交到详情的完整链路，未向生产库写入测试询盘。来源字段受浏览器策略与 UTM 缺失限制；历史会话中的“直接访问”不能当作明确的营销来源。
